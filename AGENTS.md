# Правила работы с этим репозиторием

Файл читает агент перед тем, как что-то менять. Он намеренно короткий: длинная инструкция
вытесняет из контекста саму задачу.

## Что это за проект

Сервис личных дедлайнов. Пользователь один. Главный сценарий: завести срок, утром увидеть
то, что горит, отметить выполненное.

## Как запустить и проверить

- установка зависимостей: `make install`
- запуск сервиса: `make run`
- проверки: `make test`

Любое изменение считается готовым только после того, как `make test` прошёл.

## Работа с задачами и проверка результата

- Задачи проекта ведём в GitHub Issues репозитория. Перед работой читаем описание
  задачи и проверяем, есть ли `spec.md`. Если требований для реализации не хватает,
  фиксируем, что нужно уточнить, и не придумываем поведение сервиса.
- В задаче указываем результат и проверяемые условия приёмки. Будущие изменения,
  которые зависят от спецификации, отмечаем как заблокированные до её уточнения.
- Перед завершением сверяем каждое условие приёмки с результатом и запускаем
  `make test`. Сообщаем выполненные проверки и их результат, а невыполненные
  условия и причины указываем явно. Не закрываем задачу, если проверка не прошла
  или условия приёмки не выполнены.
- После отправки изменений проверяем GitHub Actions для того же коммита и ветки.
  При использовании `make push` команда ожидает проверку и возвращает ошибку,
  если CI не прошёл или его статус недоступен. При обычном `git push` отдельно
  находим запуск CI по полному SHA коммита, ветке и событию `push` и проверяем,
  что он завершился с результатом `success`. Старый запуск или проверка другого
  коммита не подтверждает результат. Если CI не удалось проверить, сообщаем об этом
  и не закрываем задачу.

## Границы

- Файл `.env` не читать и не изменять, секреты в код не переносить.
- Зависимости не добавлять без явной просьбы, версии в `requirements.txt` закреплены.
- Менять за один заход один смысловой кусок, чтобы diff читался глазами.
- Ничего сверх того, что описано в `spec.md`, не добавлять.

## Структура

- `app/main.py` - маршруты сервиса
- `app/config.py` - настройки, читаются из окружения
- `tests/` - проверки, запускаются одной командой

## Чего в проекте пока нет

Аутентификации, уведомлений и контейнеров нет намеренно: они появятся на
следующих занятиях курса. Не добавлять их по своей инициативе.
