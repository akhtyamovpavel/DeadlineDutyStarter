# Дежурный по дедлайнам

Сквозной проект курса. К декабрю это развёрнутый сервис, которым пользуются живые люди.
Сегодня это каркас: сроки в памяти, три действия и проверка живости.

## Что делает продукт

Студент заводит дедлайн, утром открывает список того, что горит, и отмечает выполненное.
Один пользователь, один сценарий, проверяемый результат.

## Быстрый старт

```
make install
make test
make run
```

Документация после запуска на http://127.0.0.1:8000/docs

## Проверка после отправки в GitHub

GitHub Actions запускает `make test` при каждом push и pull request. Чтобы отправить
текущую ветку в `origin` и дождаться результата в терминале, запускаем `make push`.
Команда требует установленный GitHub CLI и авторизацию через `gh auth login`.
При ошибке она показывает журнал упавших шагов и ссылку на запуск. После исправления
делаем новый коммит и снова запускаем `make push`. Обычный `git push` тоже запускает CI,
но не ожидает его результат в терминале.

## Что здесь есть

- `app/` - код сервиса
- `tests/` - проверки, запускаются командой `make test`
- `.env.example` - образец файла с настройками, копируется в `.env`
- `AGENTS.md` - правила работы для агента

## Чего здесь нет намеренно

Базы данных, аутентификации, уведомлений и контейнеров. Всё это появится на своих неделях, и
появится потому, что этого потребует спецификация, а не потому, что так принято.
