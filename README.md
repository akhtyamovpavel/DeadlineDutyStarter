# Дежурный по дедлайнам

Сквозной проект курса. К декабрю это развёрнутый сервис, которым пользуются живые люди.
Сервис сохраняет сроки в SQLite, предоставляет три действия и проверку живости.

## Что делает продукт

Студент заводит дедлайн, утром открывает список того, что горит, и отмечает выполненное.
Один пользователь, один сценарий, проверяемый результат.

## Быстрый старт

Для доступа задаём переменные окружения `AUTH_USERNAME` и `AUTH_PASSWORD`. Без них
сервис не отдаёт защищённые страницы и API. Учётные данные храним вне репозитория.

```
make install
make test
make run
```

Страница сервиса после запуска доступна на http://127.0.0.1:8000/,
документация API находится на http://127.0.0.1:8000/docs. Локальный HTTP подходит
только для доверенной машины; при доступе по сети перед сервисом необходим HTTPS.
При изменении данных запросы к API должны содержать заголовок
`X-Requested-With: DeadlineDuty`.
Для сетевого доступа используем уникальный пароль и ограничиваем число попыток
входа на обратном прокси: само приложение такое ограничение не предоставляет.

По умолчанию база сохраняется в файл `deadlines.sqlite3` в каталоге запуска.
Путь к файлу можно задать переменной окружения `DEADLINES_DB_PATH`. Файл базы
создаётся при первом запуске и не включается в репозиторий.

## Отправка изменений и проверка

GitHub Actions запускает `make test` при каждом push и pull request. Перед работой
устанавливаем проверку командой `make hooks` и создаём рабочую ветку. Проверка не
разрешает отправлять изменения напрямую в основную ветку.

Первый push новой ветки возможен до создания pull request. После отправки открываем
pull request в основную ветку и запускаем `make push`. Команда проверяет CI и открытый
pull request с тем же коммитом. Если pull request ещё не создан или CI не прошёл,
команда завершится с ошибкой. Следующие отправки существующей ветки проверка разрешает
только при наличии открытого pull request. Для проверки нужны GitHub CLI и авторизация
через `gh auth login`.

## Что здесь есть

- `app/` - код сервиса
- `tests/` - проверки, запускаются командой `make test`
- `.env.example` - образец файла с настройками, копируется в `.env`
- `AGENTS.md` - правила работы для агента

## Чего здесь нет намеренно

Доступ и уведомления определяются спецификацией. Контейнеров пока нет.
