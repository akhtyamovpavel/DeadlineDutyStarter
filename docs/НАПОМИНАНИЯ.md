# Напоминания о дедлайнах

Telegram и таймер systemd выбраны как рабочий вариант для обсуждения. Канал,
получателя и расписание нужно подтвердить до включения. Шаблоны не устанавливаются
и не запускаются при обычном старте сервиса.

## Настройка

Команде нужны переменные окружения:

- `DEADLINES_DB_PATH` указывает на существующую базу приложения.
- `REMINDER_TELEGRAM_TOKEN` содержит токен Telegram-бота.
- `REMINDER_CHAT_ID` содержит идентификатор получателя.
- `REMINDER_TIMEZONE` задаёт часовой пояс IANA, например `Europe/Moscow`.
- `REMINDER_TIME` задаёт местное время в формате `09:00`.
- `REMINDER_DAYS_BEFORE` задаёт количество дней до срока от 1 до 365.

Без каждого из этих значений команда завершится с ошибкой. Бот должен иметь
возможность отправить сообщение указанному получателю. Секреты не добавляем в
репозиторий и не выводим в журнал.

Для предполагаемого Linux-сервера шаблон службы читает настройки из файла
`/etc/deadline-duty/reminders.conf`. Файл должен быть доступен только администратору.
Образец `deploy/reminders.conf.example` содержит только примеры; перед запуском
заменяем значения и согласуем расписание.
Служба запускается от пользователя `deadline-duty` и использует каталог базы
`/var/lib/deadline-duty`. Пути и учётную запись нужно согласовать с настройкой
развёртывания. После настройки службу можно проверить командой
`systemctl start deadline-reminders.service`; таймер включается отдельно командой
`systemctl enable --now deadline-reminders.timer`.

Один проход можно запустить командой `.venv/bin/python -m app.reminders` при заданных
переменных окружения. Запуск с настоящими параметрами отправляет сообщения в Telegram.

## Когда приходит сообщение

Таймер запускает проверку каждые пять минут. Команда выбирает невыполненные дедлайны
с датой ровно через заданное число дней и отправляет сообщение после наступления
указанного местного времени. Если время попало в пропущенный при переходе часов час,
проверка сработает после перехода. Пропущенный день после простоя не восполняется.

Для дедлайна и получателя сохраняется одна попытка. При успешном ответе Telegram
записывается статус `sent`, при ошибке - `failed`. Статус `attempted` означает, что
попытка началась, но результат не записан. Команда не делает автоматическую повторную
попытку: после сетевого сбоя или аварии неизвестно, принято ли сообщение. Удаление
записи попытки и повторный запуск могут привести к дублю. После ошибки проверяем
журнал службы и состояние базы, прежде чем решать вопрос о повторной отправке.

Если срок отметили выполненным после выбора и до сетевого запроса, сообщение может
уйти. Успешный ответ Telegram подтверждает приём запроса, а не прочтение сообщения.

Источники: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage) и
[systemd.timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html).
